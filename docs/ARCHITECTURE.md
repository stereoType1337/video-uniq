# Архитектура video-uniq

## 1. Что такое «вариант»

Соцсети ловят дубли по перцептивному хешу кадров, аудио-отпечатку и хешу файла, а не по
метаданным. Вариант — это точка в непрерывном пространстве параметров обработки. Метаданные —
дополнительный слой.

| Слой | Параметры | Порядок состояний |
|---|---|---|
| Геометрия | зум 1–8 %, сдвиг кадра, нечётное разрешение, pad 0–24 px, SAR | 10^5 |
| Время | скорость ±1–6 % шагом 0.1 %, fps 24–30, смещение старта | 10^3 |
| Цвет | яркость, контраст, насыщенность, оттенок, гамма, виньетка | 10^5 |
| Звук | темп, тон ±2 %, EQ, микрозадержка, стерео-ширина | 10^4 |
| Кодек | CRF/битрейт, GOP, профиль, x264 / x265 / NVENC | 10^2 |
| Метаданные | модель × версия ОС × дата × пояс × координаты × имя файла | 10^8 |

Произведение ~10^25. Миллион уникальных выходов из одного исходника — не ограничение.

## 2. Генератор без повторов

1. `seed = HMAC_SHA256(SERVICE_SECRET, f"{job_id}:{copy_index}")`.
2. Из сида детерминированно разворачивается `RenderPlan` (dataclass со всеми параметрами).
   Один и тот же вход никогда не даёт одинаковую копию; копия воспроизводима по сиду.
3. После рендера считаются: pHash 32 кадров, взятых равномерно по длительности (а не каждого
   10-го — у копий разные fps, скорость и старт, сравнение идёт по позиции в ролике),
   Chromaprint аудио, SHA-256 файла. Пишутся в `fingerprints`. Копия отклоняется, если:
   pHash до оригинала < 6 бит, до любой прежней копии того же исходника < 5 бит, BER
   Chromaprint до оригинала < 0.10 или SHA-256 совпал. Тогда перерендер с сидом
   `copy_index + 1000 * attempt`, до 4 попыток. Пороги — в `.env`, калибруются по §6.
   Замер: зум < 4 % или сдвиг тона < 0.5 % почти всегда дают копию ниже порога, поэтому
   нижние границы этих параметров в генераторе подняты.
4. Профили метаданных (`app/services/metadata.py`). Определения — в
   `app/services/data/metadata_profiles.json` (git, ревью, тесты); бот и воркер на старте
   синхронизируют их в таблицу `metadata_profiles`, а `enabled` и `weight` принадлежат
   админке (🎭 в `/admin`) и синхронизацией не перетираются. Профиль копии выбирается от её
   сида и хранится в `plan_json` и `copies.profile_id`: контейнер mp4/mov, бренд, handler'ы
   дорожек, строка кодировщика вместо `Lavc libx264`, теги (Apple `com.apple.quicktime.*`,
   Android `com.android.*`), правдоподобное время съёмки (дневное, последние 10 дней,
   UTC+1…+5) и имя файла (`IMG_8936.MOV`, `PXL_…`, `InShot_…`, `Sequence 01_20.mp4`).
   После записи патчим на месте то, что муксер не даёт выставить: `minor_version` 512 → 0
   и vendor `FFMP` → `appl` в sample entries MOV. Итог: в ftyp+moov нет ни одной строки
   FFmpeg (проверяется тестом на каждом профиле). AAC пишется с `-flags:a +bitexact`
   (иначе кодер вшивает `Lavc<версия>` в поток).
   По умолчанию — профили редакторов. Профили камер (производитель, модель, ОС) — только по
   флагу пользователя «📱 Профили камер» в настройках. GPS не подделываем.
   Стартовые профили ПРИБЛИЗИТЕЛЬНЫЕ: калибровать `python -m app.scripts.extract_profile
   --id <id> --kind <editor|camera> <реальные файлы>` и заменять записи в JSON.
   Известный остаток: handler `DataHandler` в `dref` у MOV (у iPhone — «Core Media Data
   Handler»): другая длина строки, нужна перезапись moov.

## 3. Пайплайн копии (один проход FFmpeg)

```
-ss <start_offset>
-i input
-vf  scale=<w>:<h>, crop=<cw>:<ch>:<x>:<y>, [pad=...], setsar=<sar>,
     eq=brightness=..:contrast=..:saturation=..:gamma=.., hue=h=..,
     [vignette=..], [noise=..],            # только HD+
     setpts=<speed>*PTS, fps=<fps>
-af  atempo=<1/speed>, [asetrate/aresample для тона], equalizer=..., adelay=<ms>
-c:v libx264 -preset <p> -crf <crf> -g <gop> -pix_fmt yuv420p
-c:a aac -b:a <abr>
-map_metadata -1  -metadata ... (из профиля)  -movflags +faststart+use_metadata_tags
```

Имя выходного файла — из шаблона профиля (`IMG_NNNN.mp4`, `VID_YYYYMMDD_HHMMSS.mp4`,
`reel_N.mp4`, `Sequence 01_N.mp4`). Apple-специфичные атомы при необходимости дописываются
exiftool поверх выхода FFmpeg.

## 4. Инфраструктура

- **Очередь**: arq, `queue_name=uniqualize`, `max_tries=3`, `job_timeout=3600`, `max_jobs=1` на
  воркер (FFmpeg сам занимает выданные ядра; дефолт arq — 10 задач параллельно).
- **Миграции**: `app/db/migrate.py` на старте бота и воркера, `schema_migrations` + advisory lock.
- **Воркеры**: FFmpeg, лимит 2 CPU / 2 GB на реплику, горизонтальное масштабирование по
  длине очереди. 16-ядерный дедик ≈ 15–20 копий минутного 1080p в минуту ≈ 20k копий/сутки.
  GPU-нода с NVENC для пиков (×5–8).
- **Хранилище**: локальный том `./work`, общий для бота, воркеров и `telegram-bot-api`
  (`src/` — исходники, `jobs/<id>/` — копии, `tg/` — файлы Bot API). TTL 24 ч, чистит
  cron-задача воркера раз в час. Логируются только хеши. S3 понадобится, только когда воркеры
  уедут на другие серверы (GPU-нода) или появятся прямые ссылки на скачивание в кабинете/API.
- **Telegram Bot API**: свой сервер `telegram-bot-api` в local-режиме. Облачный Bot API даёт
  ботам скачать максимум 20 МБ и отправить 50 МБ; локальный — до 2 ГБ, а файлы читаются прямо
  с диска (бот переносит их `move`, без копирования). Вебхук он шлёт по внутренней сети, так
  что Caddy для `/webhook` не нужен. Нужны `api_id`/`api_hash` с my.telegram.org.
- **Входы**: Telegram-бот (webhook), веб-кабинет (вход через Telegram Login), REST API
  (`Authorization: Bearer <token>`). Все три кладут задачи в одну очередь.
- **Поток в боте (карточка видео)**: видео → «Загружаю…» → проверки → задача-черновик
  (`status=draft`, кредиты не трогаются) и карточка: режим, число копий, звук (меняю тон /
  оригинал / без звука), цена и баланс. Выбор на карточке становится настройкой по умолчанию.
  «▶ Сделать» → `confirm_draft`: резерв кредитов и `status=queued` одной транзакцией, ровно для
  тех режима и числа копий, что видел пользователь (двойное нажатие не списывает дважды) →
  «Вы в очереди…» → arq → копии файлами **по мере готовности** с «Готово N из M» → «Готово,
  списано N кр.». Новое видео отменяет прежнюю карточку, неначатые истекают через 60 минут.
  Для «оригинала» и «без звука» аудио-проверка уникальности отключена.

## 5. Биллинг и анти-фрод

Паттерны из скилла `tg-bot-blueprint` (payments, referral), адаптированные под asyncpg и кредиты.

- **Леджер.** Баланс меняет только `ledger.apply_entry` внутри транзакции: `users.balance` и строка
  в `transactions` с `balance_after`. `CHECK (balance >= 0)` и условный `UPDATE` не дают уйти в
  минус. Виды: `trial`, `purchase`, `reserve`, `refund`, `referral`, `expire`, `admin`. Инвариант,
  который проверяют тесты: баланс = сумма записей леджера.
- **Резерв, как у Uniqly.** Цена копии: Base 1, HD 2, HD+ 3 кредита. Баланс проверяется до
  скачивания файла, задача создаётся вместе с резервом одной транзакцией (нет денег — нет задачи).
  После выдачи `settle_job` списывает только доставленные копии (`reserved * delivered / copies`),
  остальное возвращает. Повторный `settle` ничего не делает, unique-индексы на
  `(job_id, kind='reserve'|'refund')` страхуют на уровне БД.
- **Зависшие задачи.** Cron раз в 10 минут: задача финальная, но не рассчитана дольше 10 минут,
  или `processing` дольше 2 часов — закрывается как failed с полным возвратом и сообщением.
- **Оплата Telegram Stars.** `/buy` → пакет → `payments(pending)` → `send_invoice(payload=id)` →
  `pre_checkout` сверяет владельца, сумму, валюту и статус → `successful_payment` →
  `apply_verdict` — единственная точка зачисления: `FOR UPDATE`, терминальный статус идемпотентен,
  недоплата не зачисляется, уведомление только при `just_completed`. Unique-индекс на
  `(payment_id, kind='purchase')`. Пакеты (черновик): 100 кр — 250 ⭐, 300 — 650 ⭐, 1000 — 1800 ⭐.
  Карты (Tribute / ЮKassa) и крипта (Platega) — по чек-листу провайдера из blueprint, вторая очередь.
- **Сгорание.** Купленные кредиты сгорают через 30 дней после последней покупки (cron 03:05).
  Пользователи без покупок (только бесплатные и реферальные кредиты) не затрагиваются.
- **Бесплатно.** 5 кредитов при регистрации, один раз.
- **Рефералка.** `start=ref_<ref_code>`, привязка только при регистрации, самоприглашение молча
  игнорируется. Обоим по 30 кредитов после **первой доставленной обработки** приглашённого,
  один раз. Остальные аргументы `/start` сохраняются как `utm`.
- **Лимиты.** Размер 150 МБ, 2 активные задачи на пользователя, бан-лист SHA-256 исходников (TODO).

## 6. Контроль качества

Для каждой копии считается расстояние pHash и Chromaprint до оригинала; копия выдаётся
только при превышении порога. Пороги калибруются на тестовых аккаунтах (TikTok, Instagram,
YouTube Shorts) партиями по 50 копий. Это замер, который конкурент не делает.

## 7. Схема БД (черновик)

```
users(id, tg_id, username, balance, mode, copies, camera_profiles, api_token, ref_code,
      referred_by, created_at, last_purchase_at)
transactions(id, user_id, amount, kind, provider, provider_payload, created_at)
jobs(id, user_id, source_sha256, source_key, mode, copies, status, created_at, finished_at)
copies(id, job_id, copy_index, seed, plan_json, output_key, profile_id, status)
fingerprints(copy_id, phash_json, chromaprint, sha256)
metadata_profiles(id, kind, make, model, os_version, software, filename_template,
                  tz_offsets, geo_boxes, weight, enabled)
```

## 8. План работ

1. Пайплайн уникализации, генератор плана из сида, реестр отпечатков, режим Base, прогон
   тестового ролика с теми же метриками, что в `docs/COMPETITOR_UNIQUEVID.md`.
2. Кредиты, Stars, рефералка, экраны бота (меню, баланс, настройки, помощь).
3. ✅ Профили метаданных: механизм, 10 стартовых профилей, скрипт извлечения; осталось
   откалибровать профили на реальных файлах (FloreView / Daxing / Video-ACID, свои экспорты).
4. REST API, веб-кабинет, при необходимости S3 и GPU-нода.
5. Калибровка порогов на тестовых аккаунтах, оферта, лендинг.
