# Разбор конкурента: Uniqly (@UniqlyVideoBot, uniqly.video)

Дата: 2026-11-10. Источники: бот в Telegram (пройдены все меню, обработан тестовый ролик на
бесплатные кредиты), сайт uniqly.video (27 страниц из sitemap, JS-модули, публичные ответы API),
замеры копий нашим `analyze.py`. Оплату, API-ключ, режимы «Обычный» и «Зеркало», альбомы и
ссылки на рилсы не трогали.

## Кто это

- Оператор Picksa Corp, юрисдикция не раскрыта. Бот — основной канал («442 users»), плюс
  веб-студия и HTTP API (`api.uniqly.video`), баланс общий. Поддержка @kos_svat,
  support@uniqly.video. Языки EN / RU / UK, подписка на канал не нужна.
- Позиционирование узкое: **Instagram Trial Reels** и агентства (в т.ч. OnlyFans). TikTok и
  Shorts не упоминаются. Маркетинг честный: «площадка всё равно может узнать видео», процентов
  прохождения не обещают.

## Продукт и UX

- Reply-клавиатура: Баланс · Магазин · Пригласить · Помощь · Библиотека. Все экраны inline,
  редактируются на месте, есть «‹ назад». /start — GIF-туториал.
- **Выбор на карточке видео**: после загрузки «⏳ Проверяю видео…», затем карточка с режимом
  (Обычный / Сильный / Зеркало «не для Instagram»), звуком по кругу (сдвиг тона → оригинал →
  без звука), кнопками «▶ 1 / 2 / 3 копии» и счётчиком **«копий без повторов: 9 из 9»** для
  этого ролика.
- **Copy memory**: хранят хеш исходника и кадрирование каждой выданной копии (на аккаунт и
  команду), новые режут в стороне от прежних; кончились свежие кадрирования — `409
  no_fresh_framing`, совет перейти на Сильный. Копию своей же копии распознают.
- Прогресс «Готово N из 3», номера в очереди нет. Копии приходят по одной, документами
  `uniqly_v1.mp4`… Итог: списано / осталось, кнопки «Ещё копии», **«Что изменилось»** (масштаб,
  кроп, CRF, полутоны, префикс SHA-256 каждой копии), «Ещё 5 копий за 75 ⭐».
- Биллинг как у нас: резерв при приёме, списание только за выданные копии, остальное
  возвращается. На каждый сбой (обрыв загрузки, вторая вкладка) — «ничего не списано».
- Файлы в боте удаляются через 60 минут, результаты API — через 24 часа.

## Что они делают с видео (замер)

Тестовый ролик: 1080×1920, 30 fps, 8 с, H.264 CRF 20, AAC mono с тоном 440 Гц, теги
title/artist/comment. Режим «Сильный» + сдвиг тона, 3 копии.

| Копия | Разрешение | fps / длит. | Тон | pHash до оригинала | Наш порог 6 бит |
|---|---|---|---|---|---|
| v1 | 988×1756 | 30 / 8.00 с | 416.5 Гц (−0.98 пт) | 3.62 | ✗ |
| v2 | 996×1772 | 30 / 8.00 с | 420.5 Гц (−0.81 пт) | 11.19 | ✓ |
| v3 | 998×1774 | 30 / 8.00 с | 465.5 Гц (+0.97 пт) | 7.75 | ✓ |

Копия против копии: pHash min 7.81, среднее 10.15.

- Кроп ~92 % (зум ≈ 1.08) со смещением, **обратно не масштабируют** — нестандартное разрешение.
- Тон ±0.8–1 полутон без изменения темпа. Скорость, fps, длительность, цвет не меняются.
- libx264 High, CRF 18–20, случайный GOP 1.2–1.9 с, AAC 128k.
- Теги исходника удалены, **профилей устройств нет**, FFmpeg виден (`Lavf62.3.100`,
  `Lavc62.11.100 libx264`, бренды `isom/iso2avc1mp41`).
- Рендер последовательный, ~30–35 с на копию 8-секундного ролика, 3 копии ≈ 1 мин 42 с.
- Chromaprint на чистом тоне неинформативен (и у них, и у нас BER ≈ 0) — для сравнения звука
  нужен исходник с речью/музыкой.

### Мы на том же исходнике (без гейта, сырые планы)

| Режим | 3 копии | pHash до оригинала | Копия↔копия min / среднее |
|---|---|---|---|
| Base (до 720p) | 2.5 с | 6.94 / 5.44 / 11.50 | 3.69 / 8.29 |
| HD (до 1080p) | 4.6 с | 9.56 / 8.00 / 11.31 | 3.06 / 8.77 |

Плюс у нас меняются fps (28.9–30.0), длительность (±3 %), цвет и звук. Гейт в проде отбросил
бы копии ниже 6 бит до оригинала и ниже 5 бит до соседей и перерендерил их; но **минимум
копия↔копия ~3 бита** показывает, что генератору нужно активнее разводить копии между собой
(см. выводы). Локальный Mac, не сервер — скорость ориентировочная.

## Выводы для нас

Взять:
1. **Карточку видео**: режим, число копий и звук выбираются после загрузки, а не только в
   настройках; цена запуска видна сразу.
2. **«Что изменилось»** по каждой копии — у нас есть план и метрики, покажем честнее:
   pHash-дистанцию до оригинала и до соседей, сдвиг тона, скорость.
3. Копии приходят **по мере готовности** с прогрессом «Готово N из M».
4. Обработку сбоев «ничего не списано» на каждом шаге (у нас резерв уже так работает).
5. Монетизация: подписки с дневным лимитом (Pro/Team), карта и крипта, бонусы за отзывы и
   упоминания, коды креаторов — после запуска на Stars.

Обойти:
1. **Сила изменений**: у них только кроп + тон + перекод; у нас геометрия, время, цвет, звук,
   кодек и проверка каждой копии. Но надо поднять минимальную дистанцию копия↔копия: учитывать
   прежние кадрирования при генерации (их copy memory), а не только отбраковывать гейтом.
2. **Метаданные**: у них FFmpeg виден, профилей нет — наш этап 3 (профили устройств,
   правдоподобные имена файлов, Apple-атомы).
3. **Разрешение**: у них «988×1756», у нас тоже нестандартные размеры (702×1232, 1048×1826) —
   так делал и UniqueVid. Телефон снимает 1080×1920 или 720×1280, так что нестандартный размер
   сам по себе может быть признаком обработки. Решить на этапе 3 вместе с профилями: для
   профиля «камера» возвращать стандартный размер после кропа, для «редактора» — оставить.
4. **Скорость**: параллельный рендер, позиция в очереди и ETA (у них этого нет).
5. **Охват**: TikTok, Shorts, VK Клипы и горизонтальные видео, а не только Instagram.
